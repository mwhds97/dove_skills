# 长期约定（项目级）

这个工程里所有「踩过的坑 + 不许怎么做」的汇总。一份，纯 Markdown，8000 字符 / 99 行。

## 怎么读（跟你用什么工具无关）

- **只想知道这工程有哪些硬规则** → 直接打开 `项目级长期约定.md`，不用装任何东西，任何编辑器都能看。
- **想要可执行的步骤和脚本** → 看上一层目录的 15 个技能，见 `../README.md`。
- **想知道某条规则是怎么试出来的** → 逐日开发日志在开发者的工程目录里（`YYYY-MM-DD.md`，34 个 / 1.2 MB），按关键字 grep。

**内容是完整的**，不需要去找什么"原件"。这份文件就是全文，不是节选。

## 为什么单独放一份

1. **可携带**：换机器、换目录、把工程发给别人，这份文件里就带着"这个工程有哪些硬坑"。
2. **备份**：原文正好卡在某个工具的单文件读取上限上（见文末附录），继续往里加东西会把末尾吃掉，所以这里存着一份完整的。

## 这一包里的四个层级

| 层 | 位置 | 内容 | 进本包 |
|---|---|---|---|
| 项目级约定 | 本目录 `项目级长期约定.md` | 引擎硬规则、插件范式、移植口径 | ✓ |
| 项目日志 | 开发者工程的 `memory\YYYY-MM-DD.md` | 逐日流水，追加式不覆盖 | ✗（1.2 MB，每天在长） |
| 用户级约定 | 开发者机器的 `MEMORY.md` | 跨项目：称呼、沟通习惯、本机环境、git 协作 | ✗（与 Dove 无关） |
| 身份文件 | 开发者机器的 `SOUL.md` / `USER.md` / `IDENTITY.md` | 助手设定与用户画像 | ✗（纯个人） |

后三层没带是故意的：日志的用法是"按关键字搜证据"，搬进来只会让包越来越大；另外两层跟 Dove 开发没有关系。不带它们不影响你读懂、改好这个工程。

## 和技能的关系

技能是**怎么做**（步骤 + 脚本），约定是**不许怎么做**（红线 + 口径）。同一个坑通常两边都有：技能写完整流程，约定留一句索引。冲突时以约定为准 —— 那是作者踩过痛之后定下的。

## 刷新（只对维护者）

```bash
cd <Dove工程>\KingdomRushDove\mods\dove_skills

```

按字节比对，内容一致就报 `[same]`，不会无谓改写时间戳。**没有源文件的人跳过这节**：直接改 `项目级长期约定.md` 就行，不会有同步把它覆盖掉。

## 附录：8000 是怎么来的（WorkBuddy 特有，其他工具可忽略）

某个助手会在每轮对话开头把这份文件注入上下文，它有读取上限：判据是 `content.length > 8000`（按字符算，不是字节）就**从末尾**截断，且不给提示。

这就是为什么上面第 2 条"备份"成立 —— 原文现在正好 8000 字符，一个字的余量都没有，再加一条就会把末尾的「降敌人护甲只有 `SU.armor_dec` 是真的」那批经验吃掉。

用别的工具、或直接把文件丢给聊天窗口时，这些限制可能不存在，按你自己的上下文窗口算就行。
